# HAGI — русская версия с подробностями

> Русское зеркало [README.md](README.md) с расширенными объяснениями
> и математикой. При расхождении приоритет у английской версии.

В репозитории два трека:

1. **HAGI** — своя тернарная языковая модель, выращиваемая слиянием
   маленьких экспертов (не обучаем с нуля).
2. **Сжатие DeepSeek-V4-Flash (DSV4)** — эксперимент: ужать 169-ГБ
   MoE-модель до ~86 ГБ так, чтобы текст оставался связным, и считать
   прямо из сжатого представления.

## Часть 1. Цикл роста HAGI

### Идея

Большая модель = много специализированных подпространств. Дешевле
выучить маленькие доменные эксперты до насыщения и объединить их, чем
сразу обучать большую сеть.

### Математика слияния (DFT-3)

Три эксперта с весами W_A, W_B, W_C блочно-диагонально складываются в
одну большую матрицу:

```
W_block = diag(W_A, W_B, W_C)
```

Чтобы блоки начали взаимодействовать, применяется унитарный микшер
F₃ ⊗ I, где F₃ — матрица дискретного преобразования Фурье 3-го порядка:

```
      ⎡ 1   1    1  ⎤
F₃ =  ⎢ 1   ω   ω² ⎥ ,   ω = e^(2πi/3),  |F₃[j,k]| = 1/√3
      ⎣ 1   ω²   ω ⎦
```

Свойства:

- **Унитарность**: F₃† F₃ = I — преобразование не теряет и не создаёт
  энергию, градиенты текут без затухания/взрыва.
- **Равномерность**: каждый элемент по модулю 1/√3 — нет «слепых»
  каналов, каждый эксперт в равной мере влияет на каждый выход.
- **Рекурсия**: группы 3ᵏ собираются кронекеровым произведением
  F₃ᵏ = F₃ ⊗ F₃ᵏ⁻¹ (3 → 9 → 27 …).

Почему группы по ТРИ, а не по 2ᵏ: слияние степенями двойки (Hadamard)
создаёт симметричные пары каналов, в которых эксперты могут
интерферировать; тройка разносит вклады несимметрично.

### Цикл

```
корпуса → сортировка по корреляциям (unigram-профили, cos-матрица,
           жадное разбиение на декоррелированные группы)
   → обучение экспертов H=128 до насыщения (ранняя остановка)
   → безпотерное сжатие чекпоинтов (zstd-19, битово-идентично)
   → слияние троек через F₃-микшер
   → совместное дообучение слитой модели до насыщения
   → (слитая модель = «эксперт» следующего уровня, цикл повторяется)
```

## Часть 2. Сжатие DeepSeek-V4-Flash

### 2.1 Что сжимаем

DSV4 — MoE-модель: 43 слоя, в каждом 256 «routed-экспертов» +
shared-эксперты + attention. Роутер на каждый токен выбирает 6 из 256
экспертов. Эксперт — маленькая нейросеть из трёх матриц (SwiGLU):

```
x ∈ R^4096  — вход эксперта
g = W1·x + b1   (gate,  W1: 2048×4096)
u = W3·x + b3   (up,    W3: 2048×4096)
h = silu(g) ⊙ u          (silu(t) = t·σ(t))
y = W2·h + b2   (down,  W2: 4096×2048)
```

Всё остальное (attention, роутер, shared, эмбеддинги) не трогаем.
Масса routed-экспертов — 97%+ параметров модели (≈138 ГБ из 169).

### 2.2 Измерение №1: веса — белый шум (это важно!)

**Вопрос:** есть ли у экспертов общая структура, которую можно
выделить и не хранить?

**Измерение:** попарные косинусные близости матриц экспертов и спектры
сингулярных чисел каждого эксперта.

**Результат:** cos(W_i, W_j) ≈ 1/√N (N — число весов) — это значение
ожидаемо для двух случайных векторов; спектр сингулярных чисел плоский.

**Следствия (отрицательные результаты — самые ценные):**

- Никакого SVD/низкого ранга по весам: сохранять нечего.
- Любое линейное перемешивание экспертов (Hadamard/DFT/Procrustes)
  нейтрально: поворот Q сохраняет QQᵀ=I, «суммарное направление» —
  тоже белый шум.
- Единственный способ комбинировать эксперты — дистилляция
  (согласовывать выходы), не факторизация весов.

### 2.3 Измерение №2: активации НЕ низкоранговые

**Идея (ошибочная, была в начале):** входы x лежат в низкоранговом
подпространстве (топ-512 направлений объясняют ~99.9% дисперсии) —
тогда можно сжать вход разложением POD (аналог SVD для данных).

**Разоблачение:** то измерение было сделано на 3000 токенах —
переобучение. На полной выборке (259 072 токена, слой 10):

| Оставлено направлений K | Энергия (in-sample) |
|---|---|
| 512  | 59.1% |
| 1024 | 71.8% |
| 2048 | 86.2% |
| 4096 | 100%  |

Энергия e(K) = Σ_{i≤K} σᵢ² / Σ σᵢ². Хранить 512 направлений = терять
41% энергии. Низкоранговые методы по активациям отвергнуты; рефит
работает в полном ранге K=4096.

**Урок (главный принцип всего проекта):** не предполагать структуру —
измерять спектр. Каждое допущение (низкий ранг, анизотропия,
похожесть экспертов) проверяется числом до того, как на него
строится метод.

### 2.4 Метрика ошибки — и ловушка MSE

Ошибка эксперта меряется честной относительной нормой:

```
r = ‖y_квант − y_ориг‖ / ‖y_ориг‖
```

**Ловушка:** логи рефита печатают `resid` — это MSE-доля, т.е.
КВАДРАТ относительной ошибки: resid = r². Пример из практики: в логе
«0.0082» выглядит как «0.8% ошибки», на деле r = √0.0082 ≈ 9.1%.
Всегда бери sqrt от логового resid.

### 2.5 Рецепт terni4 (текущий чемпион)

Каждый вес W1/W3 округляется на тернарную решётку {−1, 0, +1} с
групповой шкалой; W2 — на int4-решётку {−7..+7} со своей шкалой.

**Групповые шкалы.** Веса разбиваются на группы по 128 подряд идущих
(в строке матрицы). Для группы g хранится один масштаб s_g, и вес
хранится как номер уровня:

```
w ≈ q · s_g ,   q ∈ {−1, 0, +1}   (W13)  или  q ∈ {−7..+7}  (W2)
```

Оптимальный по методу наименьших квадратов масштаб группы:

```
s_g* = argmin Σ_q (w_i − q_i·s)²  =  Σ q_i·w_i / Σ q_i²
```

**Почему шкала на 128 весов, а не на всю строку:** распределение весов
внутри строки неоднородно, амплитуды «гуляют»; одна шкала на строку
даёт +3-4 п.п. ошибки, на 128 — почти потолок, мельче (64) — почти
ничего не добавляет (измерено).

**Битовый бюджет.** Тернар = log₂3 ≈ 1.585 бита/вес. Упаковка:
3⁵ = 243 ≤ 256 → 5 тритов кодируются одним байтом без потерь.
W13 = 2 матрицы × 2048×4096 = 16.8М весов × 1.585 бита ≈ 3.3 МБ.
W2 = 8.4М весов × 4 бита = 4.2 МБ. Плюс шкалы/смещения ≈ 0.8 МБ.
**Итого ~8.3 МБ/эксперт против 12.6 МБ FP4 → сжатие 1.51×.**

**Честная ошибка:** ~9.5% (r на горячем эксперте). Сетка {−1,0,+1}
груба: между соседними уровнями целый «прыжок» шкалы s_g; ноль важен —
он честно «выключает» мелкие веса (решётки без нуля хуже, измерено).

### 2.6 GPTQ: квантование с компенсацией ошибки

Наивное округление (RTN) минимизирует ошибку каждого веса по
отдельности. GPTQ (OBS-теория) минимизирует ошибку ФУНКЦИИ на реальных
активациях. Ключевая математика:

Ошибка выхода квантованной строки w на строках активаций X:

```
E = ‖X·(w − q)ᵀ‖² = (w−q)·H·(w−q)ᵀ ,   H = XᵀX/n  (гессиан)
```

GPTQ идёт по колонкам j слева направо:

1. Квантует колонку j: q_j = clamp(round(w_j/s), grid).
2. Считает ошибку колонки: δ_j = (w_j − q_j)/H_jj.
3. **Продавливает ошибку в ещё не квантованные колонки** —
   корректирует их так, чтобы компенсировать уже сделанную ошибку:

```
w_k ← w_k − δ_j · H_jk    для всех k > j
```

Итог: tr(E H Eᵀ) минимизируется глобально по последовательности,
а не по отдельным весам. Ошибка int4-W2 благодаря GPTQ перестала быть
доминирующей (была 13.6% у наивного округления, теперь ~вклад нулевой
на фоне W13).

### 2.7 W2 решается через ridge (не квантуется напрямую)

W2 пишет прямо в residual-поток — его ошибка самая дорогая. Поэтому
перед квантованием W2 пересчитывается заново под уже испорченные W13:

```
h = silu(W1_кв·x) ⊙ (W3_кв·x)     # активации с квантованными W13
W2* = argmin ‖h·W2ᵀ − y‖² + λ‖W2‖² = (hᵀh + λI)⁻¹ · hᵀy
```

То есть W2 сначала «подстраивается» под ошибку W13 (закрытая форма
ridge-регрессии, λ — стабилизация), и только потом квантуется GPTQ
по гессиану hᵀh/n. Это функциональная подгонка: минимизируем ошибку
выхода y, а не расстояние между матрицами.

### 2.8 Центрирование и поворот (POD-координаты)

Вход эксперта поворачивается и центрируется:

```
z = (x − μ) @ P
```

- μ [4096] — среднее активаций слоя; эффект μ не теряется — он
  сворачивается в смещения: b ← b + μ@Wᵀ.
- P [4096×4096] — ортогональный базис слоя (из SVD ковариации
  активаций). Поворот не меняет информации (ортогональное
  преобразование), но упорядочивает энергию — GPTQ идёт от «тяжёлых»
  направлений к «лёгким», ошибка раннего квантования компенсируется
  на важных направлениях в первую очередь.

В ранних версиях P был обрезан до низкого ранга — после измерения №2
(2.3) перешли на полный ранг: P=ортогональная, без отбрасывания.

### 2.9 Телескопическая коррекция — главный механизм

**Проблема компаундинга.** Сжимаем слои независимо: слой L обучен
на чистых входах, но на инференсе получит вход, уже испорченный
сжатием слоёв 0..L−1. Ошибки перемножаются:

```
ε_L ≈ ε_{L−1}·J_L + r_L     →  e_N ~ Π(1+r_L) — экспоненциальный рост
```

**Идея (BRECQ-стиль):** фитить слой L на активациях, собранных сквозь
УЖЕ СЖАТЫЙ префикс. Тогда слой L сам компенсирует накопленный дрейф,
и ошибки складываются:

```
e_N² ≈ Σ_L w_L · r_L² ,   w_L = Π_{k>L} α_k²
```

**Измеренный A/B на слое 1** (префикс = сжатый слой 0):
- фит на чистых актах → ошибка на дрейфованных входах: **13.46%**
- фит на дрейфованных актах → **0.73%** (в 18 раз лучше)

**Перенос ошибки через слой (α).** Возмущение входа δx переносится на
выход слоя с коэффициентом (измерено инжекцией δ на слоях
1/5/12/20/30/40):

```
‖Δy‖/‖y‖ ≈ α · ‖δx‖/‖x‖ ,   α = 0.87–0.99
```

Эффективная глубина накопления ошибки (геометрическая сумма весов):

```
Σ α²ᵏ = 1/(1−α²) :  α=0.93 → 7.7 слоёв;  α=0.99 → 50 слоёв (!)
```

Отсюда прогноз полной тернарной модели: e_N ≈ r·√(1/(1−α²)).
**Осторожность:** прогноз чувствителен к хвосту α (см. 2.12).

**Важно про единицы:** это ошибка уровня эксперта. Ошибка уровня слоя
меньше — 6 экспертов на токен усредняются (если их ошибки независимы,
в √6 раз), плюс shared-эксперт и attention не сжаты.

### 2.10 Данные для фита: real-строки + unifold-синтетика

На каждый блок слоёв собирается 8К random-токенов (чанками 2048-4096),
~192 строки на эксперт в среднем (горячие до 2048). Затем рефит
усиливает покрытие синтетикой («unifold»):

- bootstrap: выборки с возвращением вокруг реальных строк;
- джиттер 10% в POD-координатах;
- **учитель бесплатен**: y_синт = W_ориг · x_синт — считаем оригинальными
  (несжатыми) весами эксперта, без прогона модели.

Синтетика сидит на дрейфованном многообразии (вокруг реальных
дрейфованных строк), поэтому телескопическая коррекция работает и на
ней.

**Открытый риск** (помечен): random-токены ≠ распределение реального
текста. Плановая проверка: собрать 2К строк реального текста сквозь
префикс и сравнить residual.

### 2.11 Лестница форматов и парето-фронт

Замерено на одном горячем эксперте (слой 5, ~2000 строк):

| Формат W13 | Биты/вес | Ошибка r | Размер/эксперт | Сжатие |
|---|---|---|---|---|
| FP4 (оригинал) | 4 | 0% | 12.6 МБ | 1.0× |
| int4 (i4i4) | 4+4 | 5.84% | ~12.6 МБ | ~1.0× (нет смысла) |
| int3 (i3i4) | 3+4 | 6.34% | 11.3 МБ | 1.12× |
| **тернар (terni4)** | **1.6+4** | **9.5%** | **8.3 МБ** | **1.51×** |
| two-level {±1,±2} | 2+4 | 8.86% | ~8.9 МБ | ~1.42× |
| бинарь (i1i4) | 1+4 | 14.3% | ~7 МБ | ~1.8× (но e_N≈39% — мусор) |

Выводы: бинарь всюду ломает текст (14.3%·√50 потенциально = 67%);
тернар — рабочий минимум; виток 2 — адаптив: горячим тернар, холодным
бинарь/two-level (вклад холодного эксперта в ошибку слоя мал:
p_k·e_k², где p_k — доля его использования).

### 2.12 Порог связности и честность гейтов

Eps-инжекция (шум в выходы FP4-экспертов): 5–10% → чистый текст,
15% → связный, 20%+ → деградация. Bisect на слоях 0-3 подтвердил:
тернарный префикс (r≈9.3-9.9%) даёт связный текст.

**Оговорка (из свежего ревью):** порог мерился белым шумом, а ошибки
квантования 6 экспертов на одном токене коррелированы (общий вход,
общий префикс) → реальное √6-усреднение может быть хуже. Честная
проверка: инжект реальных Δy (сжатый − оригинал) вместо шума.

### 2.13 KV-кэш: что произошло и как правильно

**История:** POD-сжатие KV (ранг 512→256) → измерили спектры: KV почти
полноранговые → POD отвергнут → int8-кэш (ошибка 0.003–0.005%/канал).

**RoPE-безопасные шкалы.** K хранится после поворота RoPE, который
вращает пары координат (2i, 2i+1). Шкала int8 берётся как
позиционно-независимая граница по паре:

```
scale[d] = √(max_{2i}² + max_{2i+1}²) / 127 ,  d ∈ {2i, 2i+1}
```

(максимум по всей выборке; проверено: post-RoPE максимум плоский от
позиции 0 до 500К). Для K — точно, для V — консервативно на ~3%.

**Пирамида точности (целевой дизайн).** Исходная идея пирамиды —
«дальним токенам хватит грубого припоминания» — верна, но её первый
носитель (ранг) умер вместе с POD. Правильный носитель — битовая
глубина:

```
дистанция d до токена:
  d < 4K (окно)        → bf16/int8  (полная точность)
  средняя дистанция    → int8       (ошибка ничтожна на фоне 9.5% экспертной)
  d ≥ 64K (история)    → int4       (биты вдвое на удвоение дистанции —
                                     тот же закон r(d)=base>>⌊log₂(d/w)⌋,
                                     применённый к битам, а не к рангу)
  sink-токены          → полная точность
```

**Математика оправдания:** вклад ошибки токена t в выход пропорлен
его softmax-весу a_t: ошибка выхода ≈ Σ_t a_t·δ_t. Дальний токен имеет
малое a_t → его грубое квантование входит в выход с малым
коэффициентом. Бюджет ошибки — по вкладу, а не поровну. Это тот же
телескопический принцип, что и у экспертов (2.9).

На контексте 2М: ~3–4× экономии кэша против bf16, потому что
доминирующая доля токенов — дальняя история.

**Подключение:** после e2e-гейта тернарной модели — plain int8-KV в
генератор (одна строка); двухуровневая пирамида — патч к Int8KVStore
(токены, вытесненные из окна, переупаковываются в int4), нужна только
для контекстов >128К.

### 2.14 Полный список отвергнутого (не повторять)

Каждое — измерением, не мнением:

| Что | Почему отвергнуто |
|---|---|
| SVD/низкий ранг весов | плоский спектр, белый шум |
| POD активаций K=512 | 41% энергии теряется out-of-sample |
| Whitening | анизотропия мала, не окупает накладные |
| Поворот h (W2-вход) | silu полумёртв, λ-разброс ковариации 1.5e12 |
| Поворот y (QuIP#) | 141%, размазывает тяжёлые строки |
| Канальное перемасштабирование W3↔W2 | доказуемо инвариантно (d·1/d сокращается) |
| Знаковые ветви ±α | 7.47% > 6.34% равномерного int3 |
| k-means кодбуки | 6.47% > 6.34%, а хранить кодбуку дороже |
| KL-Root-Kron, act_order | без выигрыша |
| Решётки без нуля | ноль в тернаре критичен |

### 2.16 TTT — онлайн-аналог телескопической коррекции

TTT (test-time training) — anchored RLS-подстройка readout-матриц
прямо во время генерации: модель непрерывно компенсирует собственный
дрейф на реальных данных инференса. Это непрерывный аналог
послойной телескопической коррекции (2.9): то же «фит на факте»,
только онлайн и малыми рангами. Адаптации сохраняются как
низкоранговые дельты.
