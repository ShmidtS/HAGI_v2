# HAGI (русская версия)

> Этот файл — русское зеркало [README.md](README.md). При расхождении
> приоритет у английской версии.

HAGI — **тернарная RD-канальная каузальная языковая модель**:
источник-кодер → (опциональный мультимодальный мост) → тернарный
трансформер-канал → tied-ресивер.

Текущая архитектура — **V42** (`hagi-channel-v42`): полное каузальное
внимание + T=512 + perforated-ресивер. См.
[docs/V42_ARCHITECTURE.md](docs/V42_ARCHITECTURE.md).

## Алгоритм цикла роста

HAGI выращивает большую модель из маленьких доменных экспертов вместо
обучения с нуля. Идея и результаты — в
[GROWING_HYPOTHESIS.md](GROWING_HYPOTHESIS.md).

Текущий конвейер — **рекурсивный тернарный цикл роста**: слияние всегда
**группами по три** через комплексный DFT-3 (F₃)-микшер, никогда степенями
двойки. Полный драйвер: `scripts/run_growth_cycle.sh`.

Цикл на каждом уровне:

1. **Сортировка корпусов в слабокоррелированные домены.**
   `scripts/analyze_corpora.py` строит униграммный профиль каждого корпуса,
   считает матрицу парных корреляций и жадно разбивает корпуса на
   декоррелированные группы. Слабая корреляция (например, RU ↔ EN
   отрицательна) заставляет каждого эксперта специализироваться на
   действительно разных подпространствах.
2. **Обучение маленьких экспертов (H=128) до насыщения.** Эксперты учатся
   по одному с ранней остановкой по насыщению (`saturation_patience`,
   `saturation_tol`, `saturation_min_steps`), а не по фиксируемому числу
   шагов.
3. **Безпотерное сжатие.** `scripts/compact_checkpoint.py` пакует каждый
   чекпоинт zstd (уровень 19) без потери информации; восстановление
   битово-идентично (проверено).
4. **Слияние трёх экспертов через тернарный DFT-3-микшер.**
   `scripts/merge_experts.py` блочно-диагонально складывает экспертов и
   рекомбинирует унитарным F₃ ⊗ I-микшером (`mixer_hadamard_groups: [3]`).
   F₃ унитарен, каждый элемент имеет модуль 1/√3 — равномерное смешивание
   без слепых каналов. Группы размера 3ᵏ (3, 9, 27, …) поддерживаются
   кронекеровой рекурсией F₃ᵏ.
5. **Совместное обучение слитой модели до насыщения.** Учит
   рекомбинированные блоки взаимодействовать; тоже с ранней остановкой
   по насыщению.

Слитая модель H=384 сама может считаться экспертом уровня 1, так что цикл
рекурсивен (3 → 9 → 27 эквивалентов эксперта с точностью до перестановки
каналов).

### Скрипты

- `scripts/analyze_corpora.py` — корреляционный анализ корпусов / сортировка доменов.
- `scripts/train.py` — обучение / resume / init-from (с учётом насыщения).
- `scripts/compact_checkpoint.py` — безпотерное zstd-сжатие чекпоинтов.
- `scripts/merge_experts.py` — низкоуровневый CLI блочно-диагонального слияния (DFT-3).
- `scripts/run_growth_cycle.sh` — сквозной драйвер цикла роста.
- `scripts/compact_model.py` — эксперименты с геометрией (повороты / SVD / сортировка).

### Конфиги

- `configs/level0_experts/expert_*.yaml` — маленькие (H=128) доменные эксперты
  (ru_general / en_general / math_code / instruct).
- `configs/level0_merged_3.yaml` — слитая модель H=384 (тернарный DFT-3-микшер
  `mixer_hadamard_groups: [3]`, обучение по насыщению).

## Сжатие MoE DeepSeek-V4 (статус: в работе)

Эксперимент по сжатию DeepSeek-V4-Flash
(256 routed-экспертов/слой × 43 слоя = 11008 экспертов) с минимальной
потерей качества. Находки ниже актуальны на момент последних измерений.

### Что держится: веса — белый шум

Измерено на реальном чекпоинте: routed-эксперты попарно ортогональны
(cos ≈ 1/√N, плоский спектр сингулярных чисел) — каждая матрица весов
является белым шумом. Любое линейное перемешивание — Hadamard, DFT-3,
Procrustes — нейтрально по информации: поворот сохраняет матрицу Грама,
«суммарный» канал — просто ещё одно случайное направление. Общей
компоненты для восстановления **нет**; единственный способ комбинировать
эксперты — дистилляция (копирование выходов), но не факторизация весов.
SVD по весам мёртв: полный ранг, плоский спектр.

### Что было неверным (исправлено): активации — НЕ низкоранговые

Более раннее утверждение — «топ-512 входных направлений объясняют 99.93%
дисперсии» — было артефактом переобучения: измерялось на N=3000 токенов.
Честный спектр (полная выборка 259072 токена, слой 10) почти полноранговый:

| K (оставлено направлений) | энергия, in-sample | out-of-sample |
| --- | --- | --- |
| 512 | 59.1% | ~41% |
| 1024 | 71.8% | — |
| 2048 | 86.2% | — |
| 3072 | 94.9% | — |
| 4096 | 100% | — |

Сжатие residual-потока до K=512 теряет ~40% энергии, низкоранговое POD-
сжатие активаций **отвергнуто**. Рефит работает на полном ранге (K=4096).

### Текущее сжатие (на эксперт)

Каждый routed-эксперт 4096→4096 заменяется полноранговым блоком со
смешанной точностью — без POD-бутылочного горлышка, без выходного базиса:

```
z = (x - mu) @ P                        # центрирование по среднему слоя + ортогональный поворот
g = soft_lim(z @ W1ᵀ + b1)              # W1: тернар {−1,0,1}, групповые шкалы g128
u = soft_lim(z @ W3ᵀ + b3)              # W3: тернар {−1,0,1}, групповые шкалы g128
y = (silu(g) * u) @ W2ᵀ                 # W2: int4-сетка ±7, шкалы g32, GPTQ
```

- **P** [4096×4096] fp32 — поворотный базис слоя; **mu** [1×4096]
  сворачивается в смещения b1/b3 (центрирование + свёртка среднего в bias).
- **W1, W3** (gate/up): **тернар {−1,0,1}**, ~1.6 бита/вес (5 тритов/байт),
  групповые шкалы [out, 32] (128 весов на шкалу), GPTQ по гессиану
  активаций.
- **W2** (down): **int4-сетка ±7**, 4 бита/вес, шкалы g32,
  GPTQ/LDLQ-компенсация ошибки по гессиану `H = hᵀh / n` (h считается с уже
  квантованными W13). GPTQ минимизирует *функциональную* ошибку выхода, а не
  ошибку весов — это убрало W2 из доминирующих источников ошибки.
- Адаптивный Cholesky-джиттер для тонких экспертов (n < 2048 строк →
  неполный ранг гессиана); маркер режима `terni4` хранится в каждом файле.

**Размер**: ~8.3 МБ/эксперт против 12.6 МБ FP4 = **сжатие 1.51×** массы
routed-экспертов (97%+ параметров модели).

**Честное качество** (норма ошибки ‖y_pred−y‖/‖y‖ на эксперт, на реальных
активациях): ~9.5% на горячем эксперте. Примечание: логи рефита печатают
*квадрат* относительной ошибки (MSE-доля) — для нормы ошибки берите
`sqrt(resid)`. Пол тернарной схемы — сам тернарный W13; вклад int4 W2
благодаря GPTQ почти нулевой. Бенчмарк с eps-инжекцией (шум в выходы FP4-
экспертов): 5–10% → чистый текст, 15% → связный, 20%+ → деградация.

### Настоящий рычаг по памяти: int8-квантование

Поскольку активации полноранговые, выигрыш по памяти даёт квантование,
а не низкий ранг:

- **int8-активации (residual-поток)** — поканально, ~2× при ~0.01% ошибки
  реконструкции (на тензор ~0.08%).
- **int8 KV-кэш** — поканальная статическая шкала, RoPE-безопасная (K
  хранится после RoPE; граница шкалы — rotation-safe максимум по каждой
  RoPE-паре, не зависит от позиции, проверено плоским до 500K позиций),
  ~2× при ~0.005% ошибки (худшее 0.0125% по 43 слоям). Заменяет прежний
  низкоранговый KV-POD (512→256), который был отвергнут: измеренные
  спектры KV почти полноранговые, допущение низкого ранга было неверно
  с самого начала — тот же урок, что whitening/повороты в треке
  экспертов: сначала измерь спектр, потом выбирай метод.

**Целевой дизайн KV — пирамида точности** (старая идея пирамиды жива,
на правильном носителе). Исходная KV-POD-пирамида (2531698) делила пополам
*ранг* чтения на каждое удвоение дистанции; носитель «ранг» умер вместе с
POD. Выживает принцип: ближние токены важнее, дальние получают малые
softmax-веса, их ошибка входит в выход задемпфированной. Распределяй
бюджет ошибки по вкладу, а не поровну — тот же телескопический принцип,
что и в рефите экспертов:

- скользящее окно (~4K) — полная точность (bf16 или int8);
- средние дистанции — int8 (0.003–0.005% на канал, ничтожно на фоне 9.5%
  ошибки сжатия эксперта);
- дальняя история (≥64K) — int4 (деление эффективных бит вдвое на каждое
  удвоение дистанции — тот же закон, что у старого `r(d)`, применённый к
  битовой глубине);
- несколько sink-токенов — полная точность.

На контексте 2M это в ~3–4 раза меньше bf16-кэша без заметной деградации
(доминирующая доля токенов — дальняя история). План подключения: обычный
int8-KV включается в TTT-генератор после тернарного e2e-гейта (однострочный
install); двухуровневая int8/int4-пирамида — маленький патч к
`Int8KVStore` (токены, вытесненные из окна, переупаковываются в int4),
нужен только для контекстов >128K.

### Пробовали и отвергли (поиск по квантованию)

Описанная схема — измеренный парето-оптимум при ~2× на скалярных сетках;
альтернативы были спрототипированы и отвергнуты измерением:

- **SVD / низкий ранг по весам** — плоский спектр, сохранять нечего.
- **Низкоранговый POD активаций (K=512)** — ~40% потери энергии out-of-sample.
- **Выходной базис Q через int4-QAT** — бутылочное горлышко без выгоды на полном ранге.
- **Низкоранговый KV-POD (512→256)** — заменён int8 (оба 2×, int8 теряет меньше).
- **Линейное перемешивание (Hadamard / DFT-3 / Procrustes)** — ортогональные
  эксперты остаются ортогональными.
- **E8-решёточное квантование (GLQ/QuIP#)** — 36.8% ошибки нормы, хуже int4.
- **Сферическое VQ @ 2.25 bpw** — 39.2% (rate-distortion-предел: 2.25 бита ≠ 4 бита).
- **2-стадийное VQ @ ~4.25 bpw** — 15.3%, но требует fp16-шкал на группу →
  размер как у int8, бухгалтерская иллюзия.
- **2/3-битные сетки W13** — без выигрыша против тернаря с нулём.
- **Поколоночные/более мелкие шкалы W13** — помогали только в несохраняемом
  формате; честные групповые шкалы на W13 ≈ +0.1%.
- **Низкоранговая коррекция дельты квантования W2** — диффузный спектр, тупик.
- **Наивный (CD/RTN) int4 W2** — 13.6% вклада от одного W2; заменён GPTQ.
- **Whitening, замороженные шкалы, h/y-повороты (QuIP#), знаковые ветви,
  k-means-кодбуки, канальное перемасштабирование W3↔W2 (инвариантно),
  KL-Root-Kron, act_order, решётки без нуля** — всё хуже локальных
  групповых шкал + тернарной сетки.

Кросс-валидация с индустрией: Tencent/AngelSlim Hy4 GGUF (тернарный
3:4-разреженный gate/up ~1.3–2 bpw, down-проекция сознательно на 2 уровня
выше «потому что пишет прямо в residual-поток», LS-шкалы вместо amax = 90%
их PTQ-выигрыша, разбивка чувствительности по слоям) совпадается с нашей
схемой смешанной точности и выбором LS-шкал.

### Статус

Рецепт-победитель — **`terni4`**: тернарный W13 (сетка {−1,0,1}, GPTQ,
групповые шкалы g128, 5 тритов/байт) + int4 GPTQ W2 (g32) — **1.51×**
против FP4-оригинала, e2e-гейт связности на слоях 0–3 пройден.
Измеренная RMS-ошибка на эксперт ~9.5% (горячий эксперт, честная
‖Δy‖/‖y‖); бинарный W13 везде отвергнут (~14.3%/эксперт → e_N ≈ 39% при
компаундинге). Следующий виток: адаптив терн-горячие / бинарь-холодные
эксперты (~1.6–1.9×).

Полный проход по 43 слоям идёт **последовательно с телескопической
коррекцией** (в духе BRECQ): каждый слой фittится на активациях,
собранных сквозь уже сжатый префикс, поэтому ошибки слоёв складываются
(Σ), а не перемножаются (Π). A/B на слое 1: фит на дрейфованных актах
**0.73%** против чистого фита **13.46%** — 18× в пользу; перенос ошибки
между слоями α = 0.87–0.99. `seq_full_pass.sh` оркестрирует проход блоками
по 3 (сбор 3 слоёв за один прогон модели → рефит → освобождение актов,
~14 ч всего).

Примечание о метриках: логи рефита печатают `resid` как **MSE-долю**
(квадрат относительной ошибки); честная RMS-ошибка — `sqrt(resid)`
(например, 0.0082 в логе ≈ 9.1% RMS). Не читайте логовые residual'ы как
проценты.

Генерация идёт из сжатых файлов экспертов через
`scripts/dsv4_generate_ttt.py` (`INT4X_OFF=1` → FP4-базлайн для A/B).
Поверх файлов конвейер поддерживает **TTT** (anchored RLS «eternal
thinking») обновления и `--evolve` self-talk-сессии.

### Пайплайн

```
lossless_layers/{layer}_ffn.safetensors   (FP4 routed-эксперты)
        │  dsv4_experts.py (dequant_fp4, pack/unpack intN/binary/ternary)
        ▼
dsv4_collect_seq.py    ── сбор дрейфованных x/y для слоёв L..L+2 сквозь
        │                 сжатый префикс (SEQ_LAYERS, I4X_LAYERS,
        │                 чанк SEQ_CH; 8K random-токенов + unifold-посев)
        ▼
dsv4_refit_experts.py <L>   ── PTQ: тернар W13 + GPTQ int4 W2 на
        │                     дрейфованных актах (W13_MODE=tern W13_BITS=2
        │                     W13_GS=128 W2_GPTQ=1 PTQ_ONLY=1)
        ▼
dsv4_reduced/layer_<L>/P.pt, mu.pt, expert_<k>.pt   (режим "terni4")
        ▼
dsv4_generate_ttt.py        ── декод из упакованных файлов на лету (+TTT/evolve)
```

Ключевые скрипты:

- `scripts/dsv4_experts.py` — общие утилиты декода/упаковки
  (binary, ternary, int4, n-bit, int6).
- `scripts/dsv4_refit_experts.py` — поэкспертный PTQ-рефит (терн/бинарь
  W13, GPTQ W2 по гессиану активаций; env `W13_MODE`/`W2_GPTQ`).
- `scripts/dsv4_collect_seq.py` — последовательный сборщик дрейфа
  (мульти-слойный захват за один прогон модели, чанки для стабильности HIP).
- `scripts/probe_alpha.py` — измерение переноса ошибки α между слоями.
- `scripts/probe_binary_check.py` — честная ошибка по форматам на реальном
  эксперте (бинарь vs тернар vs two-level; env `PROBE_L`/`PROBE_K`).
- `scripts/eval_ab_layer1.py` — A/B-оценка варианта рефита на held-out
  строках (`drift` vs `clean` фиты).
- `seq_full_pass.sh` — полный последовательный тернарный проход 43 слоёв
  (блоки по 3, гигиена диска, lock на один экземпляр).
- `scripts/dsv4_generate_ttt.py` — генерация из сжатых файлов
  (`INT4X_OFF=1` → FP4-базлайн; `EXPERT_NOISE=ε` → шумовой бенчмарк).
- `scripts/dsv4_kvcache_int8.py` + `scripts/dsv4_generate_int8kv.py` —
  int8-KV-трек (шкалы, стора, генератор).
- `scripts/triton_kernels.py` + `scripts/build_bank.py` — ассеты трека
  ускорения (декод из упакованных весов, банки экспертов; адаптация под
  тритовую упаковку — после e2e-гейта).
