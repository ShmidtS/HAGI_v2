# GROWING_HYPOTHESIS — «Модульное иерархическое расширение представительных пространств»

## Гипотеза

Большая модель, обученная с нуля, тратит раннюю часть compute на *открытие*
специализированных представлений (доменно-специфичных признаков), которые
затем композируются. Если вместо этого обучить N малых экспертов до насыщения
на N непересекающихся корпусах, каждый эксперт уже имеет хорошо сформированное
доменно-настроенное скрытое пространство. Конкатенация этих пространств
блочно-диагонально в одну широкую модель даёт большой модели фору: она
наследует N готовых специализированных подпространств вместо того, чтобы
открывать их с нуля.

## Механизм (реализован в `src/hagi/model/merge.py`)

- **Блочно-диагональная инициализация**: `W_Q = diag(W_Q^A, ..., W_Q^N)` (и
  аналогично для KV, out, FFN). На шаге 0 merged-модель — это *точно* N
  независимых экспертов (off-diagonal блоки нулевые).
- **Cross-Expert Mixer**: лёгкий SwiGLU-слой на residual stream, gain=0
  (identity). Единственные новые параметры — связи между блоками.
- **Короткое совместное обучение**: mixer gain растёт от 0, блоки учатся
  обмениваться информацией.

## Результаты эксперимента (4 эксперта, 20000 шагов + 2000 joint)

### 1. Специализация сохраняется после объединения

| Домен | Лучший эксперт | Merged после joint | Δ |
|---|---|---|---|
| RU | 6.00 | 5.70 | **-0.30** |
| EN | 5.48 | 5.05 | **-0.43** |
| MATH | 5.32 | 5.07 | **-0.25** |
| CODE | 3.39 | 3.41 | +0.02 |

Merged-модель сохраняет каждую специализацию и даже **улучшает** её на
большинстве доменов (RU/EN/MATH) — блоки обмениваются информацией.

### 2. Короткое взаимодействие восстанавливает/улучшает общее качество

| Модель | AVG exact CE |
|---|---|
| Лучший отдельный эксперт (EN) | 6.42 |
| Merged step 0 (до joint, logit_scale не нормирован) | 9.00 |
| Merged step 0 (до joint, logit_scale / sqrt(N)) | 6.39 |
| **Merged после 2000 joint** | **4.83** |

**Ключевой результат**: 2000 шагов joint (65M токенов, ~2.4% бюджета)
снижают AVG с 6.39 до 4.83 — ЛУЧШЕ, чем любой отдельный эксперт (6.42).
Короткое взаимодействие не просто восстанавливает качество, а улучшает его
за счёт композиции специализаций.

> **Баг logit_scale**: без деления на sqrt(N) merged head-проекция (concat по
> input) суммирует N вкладов → logits в ~N раз острее → step 0 AVG=9.00.
> Нормализация (как в grow.py) даёт step 0 AVG=6.39 — joint стартует с
> лучшей точки.

### 3. Масштабирование vs обучение с нуля

**Сравнение при равном бюджете общего обучения (49M токенов):**

| Модель | RU | EN | MATH | CODE | AVG |
|---|---|---|---|---|---|
| **Merged (2000 joint)** | **5.72** | **5.09** | **5.05** | **3.47** | **4.83** |
| Baseline (2000 шагов) | 6.63 | 5.36 | 5.43 | 4.35 | 5.44 |

**Merged превосходит baseline на 0.61 exact CE** при том же бюджете общего
обучения. Гипотеза подтверждается: выращивание из экспертов эффективнее
обучения с нуля на сопоставимом бюджете.

> Примечание: эксперты обучались на отдельных доменах (каждый 2.6B токенов
> своего домена) + 2000 joint (65M токенов mixed). Baseline — 2000 шагов
> (49M токенов mixed). Merged суммарно видел больше токенов, но по бюджету
> *общего* обучения (joint vs baseline) сравнение честное.

## Уточнённая scaling-гипотеза

1. **Специализация — это «бесплатный» параллелизм**: N экспертов обучаются
   независимо (можно параллельно на N GPU), каждый открывает своё
   подпространство. Это аналог data-parallel, но по *доменам*, а не по
   батчам — каждый эксперт развивает разные представления.

2. **Merge — это «композиция готовых подпространств»**: блочно-диагональная
   инициализация сохраняет специализации точно (step 0 = N экспертов).
   Единственная потеря — head не знает, какой блок активен (AVG=8.23).

3. **Joint — это «обучение композиции»**: mixer + head учатся использовать
   правильные блоки. 200 шагов достаточно, потому что блоки уже
   сформированы — нужно только научить их взаимодействовать.

4. **Иерархия**: объединение по группам (16→4→1) может дать преимущество,
   потому что на каждом уровне mixer учится композиции подпространств
   меньшей размерности, что проще, чем сразу 16 блоков.

## Иерархический эксперимент (4→2→1, ЧАСТЬ IV)

Проверка иерархии: 4 насыщенных эксперта (H=128) → 2 группы (H=256,
RU+EN и MATH+CODE) → финальная H=512. Каждый уровень дообучается joint.

### Результаты (равный бюджет 49M токенов общего обучения)

| Модель | RU | EN | MATH | CODE | AVG |
|---|---|---|---|---|---|
| Flat merged (2000 joint) | 5.72 | 5.09 | 5.05 | 3.47 | 4.83 |
| **Hierarchical merged (2000 joint)** | **5.67** | **5.07** | **5.04** | **3.48** | **4.81** |
| Baseline (2000 шагов) | 6.63 | 5.36 | 5.43 | 4.35 | 5.44 |

**Вывод**: после исправления logit_scale иерархия (4→2→1) и flat merge (4→1)
дают практически одинаковый результат (4.81 vs 4.83). Оба превосходят
baseline (5.44). Ранее иерархия была хуже (5.00) из-за неверного logit_scale
на промежуточном уровне — это был артефакт, а не свойство иерархии.

## Следующее поколение: «модульное иерархическое расширение»

Концепция: вместо обучения одной большой модели с нуля —
1. Обучить N малых экспертов на доменах (параллельно, дешёво).
2. Блочно-диагонально объединить в широкую модель (сохраняя специализации).
3. Короткое joint-обучение mixer (обучение композиции).
4. Иерархически повторить (объединить группы, дообучить, объединить снова).

Это даёт: (a) параллелизм по доменам, (b) сохранение специализаций,
(c) дешёвое обучение композиции вместо дорогого открытия представлений.
