## Interference Search (Bad Theory Labs, сентябрь 2026)

- paper: https://www.badtheorylabs.com/papers/interference-search/paper.pdf
- code: https://github.com/Badtheorylabs/interference-search

### Что это

Breadth-first поиск по явным состояниям вместо цепочки рассуждений. Все живые
ветви расширяются одновременно; состояния склеиваются по ключу; судья
оценивает пул; выживают W лучших. «Интерференция» — метафора, формальной
величины нет. Автор признаёт: метод классический, квантового ускорения нет.

Домен задаёт шесть функций: `start`, `propose`, `key`, `judge`, `is_goal`,
`is_dead`. Транскрипт не переносится — каждое предложение видит одно
состояние.

### Числа автора

| что | результат |
|-----|-----------|
| Countdown 4 числа, 200 позиций | фронтир 30/30, линия 21/30 |
| шагов до решения всех 30 | 3.0 против 23.7 |
| сжатие состояний | 4 числа → 3.6×, 5 → 11.4×, 6 → 62.8× |
| доля путей через мёртвое состояние | 95.4% / 96.2% / 82.6% |
| judge (100k параметров) на лёгких задачах | 10.7× отсечения, 0 потерь |
| judge на сложных, τ=0.7 | падает до 43% |
| Qwen3-1.7B CoT | 3/30 |
| MBPP | IS 9, best-of-N 8, agent-loop 7 — в пределах шума |

Одна авторская линия, без рецензирования, репликаций не найдено. Демо сначала
выдавало Opus, на деле был Qwen3-1.7B.

### Что переносится

**Форма цикла**, не цифры: склейка по эквивалентному поведению, синхронное
продвижение по уровням, дешёвый судья на простых признаках. Их probe по
числовым признакам дал AUC 0.94 при обучении на 632k состояний — готовая
дешёвая замена обучаемому судье.

### Что НЕ переносится

1. **Состояние должно быть хешируемым.** Для генерации это префикс токенов;
   одинаковые префиксы редки. Автор сам признаёт: модель повторяет
   *содержание*, но не *идентичные состояния*, поэтому ему пришлось вручную
   подавать мультимножества чисел. Наш ближайший аналог — эквивалентность по
   поведению на тестах.

2. **Нужен точный судья.** Все 10.7× отсечения держатся на том, что в Countdown
   есть DP-решатель, точно помечающий aliveness. В открытой генерации судью
   надо обучать, и авторские числа не переносятся.

3. **Масштаб.** 1.7B получает 3/30; наша модель ~100-300M слабее, так что
   аргумент направлен в нужную сторону. Но автор сам показывает, что три
   дешёвых вмешательства *внутри* модели — текстовый леджер, ревинд,
   state-prompting — все провалились (ревинд регенерировал ту же строку 16
   раз; state-prompting решил 0). Сработало только вынесенное наружу.

4. **Главное число не использует модель.** 30 против 21 — это среда плюс
   100k-судья. Единственное сравнение с реальной моделью (MBPP) — 9 против 8.

### Вердикт

**Не влияет на цикл роста.** Мы растём через слияние экспертов; это про
инициализацию, а не про поиск рассуждений. Merge-эффект 0.47-0.79 ната —
другой механизм, interference-search его не объясняет и не улучшает.

**Применимо к генерации.** Наш decode одноцикл: один префикс, без склейки.
Фронтир с W параллельных ветвей и склейкой по эквивалентному поведению —
разумный каркас для задач, где проверка исполняемым тестом даёт точного
судью (в отличие от Countdown, где он был искусственным). Ожидание: единицы
процентов, не 30/30.

Статус: не реализовано. Готовность — отдельный режим в `infer.py` плюс
измерение на MBPP.

## Раунд 2 (2026-09-26): дерево с корой

Три источника присланы пользователем вместе с указанием модернизировать
архитектуру. Оценка по тому же правилу: принимаем примитив, а не репозиторий.

### Cache-to-Cache (arXiv 2510.03215v2) — ПРИНЯТО, механизм

Fu, Min, Zhang, Yan, Dai, Ouyang, Wang (Tsinghua / Infinigence / SJTU / CUHK).
Замороженные модели общаются напрямую через KV-кэш, обучается только
«фьюзер» `F`:

```
C^F_n = C_n(X) + F_n( C_n(X), C^S_{G(n)}(X) )
```

Важное для нас — не про кэш, а про **остаточную инъекцию в составную
глубину**. Их абляция: перезапись 20.70 → +остаточный fuse 44.88 →
+гейт 47.95. То есть сам по себе аддитивный канал почти не помогает
(−0.5 против перезаписи на их метрике), помогает **гейт на этом канале**.

Что берём: **per-edge Gumbel-sigmoid гейт с отжигом температуры**,
нулевой инициализацией и замороженным носителем. У C2C нулевой инициализации
нет (у нас есть — не теряем). Отображение слоёв — терминальное
выравнивание (последний↔последний, назад); их `argmin` по нормированной
глубине работал хуже.

Чего в статье нет: рекурсии. Composition строго попарный, M-sharer /
N-receiver — заглушка в приложении, стоимость O(N) названа открытым
вопросом. Поэтому она не отвечает на «растёт ли дерево в глубину», она
отвечает на «как сделать межуровневой канал безопасным».

### quail (fsdatalab/quail) — ОТКЛОНЕНО для роста, кандидат для декода

AI-SQL движок (CMU Full Stack Data Lab): планировщик + GPU-исполнитель
LLM-операторов по строкам. `executor/moe.py::FP8Experts` — обёртка над
Triton FP8 ядрами vLLM, это инференш роутинга, а не композиция обученных
экспертов. Слияния моделей нет. Cross-layer routing нет.

Единственный перенос: `attention.py::attention_merge_quant` сливает два
результата внимания по LSE-весу
`w = sigmoid(lse_b − lse_a); merged = a + (b−a)·w` (Milakov & Gimelshein
2018). Скаляр доверия на ряд/голову вместо фиксированных коэффициентов.
Кандидат на будущее для генерации, не для цикла роста.

ROCm: мёртв. Capability-гейт допускает только `(9,0)` H100 и `(12,0)`,
зависит от vLLM 0.26 + DeepGEMM fp8.

### openjev (TheoLeeCJ/SemIf-OpenJev) — ОТКЛОНЕНО

Переименован. Скоринг семантических решений по логитам замороженной модели
без генерации. Ни train loop, ни оптимизатора, ни роста — только
`model.eval()` + `inference_mode()`. К слиянию экспертов отношения не имеет.

### Итог по архитектуре

Модернизация собирается из двух независимых вкладов, и оба нужны:

| вклад | источник | что определяет |
|-------|----------|----------------|
| root-мода | `docs/ARCHITECTURE_V2.md`, наш анализ F3-инварианта | **куда** писать: только диагональ `(1,1,1)`, значит равенство листьев сохраняется |
| per-edge гейт + отжиг | Cache-to-Cache | **сколько** писать: обучаемый скаляр, ноль на старте, бинарный на инференсе |

Запрет `ternary_f3 requires cortex disabled` был верен для **плотной**
коры (она нарушает равенство листьев на шаге 0) и слишком широк для
root-моды. Снимаем только для root-моды, с гейтом. Детские заборы
(`cortex.*` запрещён в состояниях детей, `child_m.cortex.enabled`
отвергается) остаются: рёбра коры описывают взаимодействия уровней,
которых у ребёнка не было.
