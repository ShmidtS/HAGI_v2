## Производительность

- Attention: fp32-ручной путь 5.60 мс/слой → fused AOTriton flash 0.79 мс при
  `[64,18,128,64]`.
- arm S: 6.25 → 8.15 шага/с (+30%). N=6 joint: 3.11 шага/с.
- Причина выигрыша: без `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` на этой
  GPU доступен только MATH-бэкенд SDPA, «fused» вызов молча разворачивался в
  три отдельных matmul.

## Что эти числа НЕ доказывают

**Всё это — плоское слияние, один уровень.** N экспертов → одна модель,
`mixer_type="swiglu"`, `loop_depth: 1`, `ternary_depth` не использовался.
`merge_recursive_f3` / `RecursiveF3HAGI` (тернарное дерево) не запускались
ни разу: ни одного конфига с `ternary_f3`, ни одного чекпойнта.

Поэтому исходная гипотеза — что рост идёт **в глубину** дерева, а не в его
ширину — не проверена. Измерено только то, что слияние работает, и работает
лучше, чем ёмкость.

## Отозванные числа

M/C/S из ранних прогонов (5.9534 / 6.2232 / 7.9455 / 6.5128) получены
`eval_holdout.py`, который писал `out.loss` в поле `exact_ce`. При
`sampled_softmax_k=2048` это sampled NCE, а не полный CE: замеренный разрыв
7.6246 против 11.7285, то есть занижение на 4.10 ната. Плюс merged-рука была
обучена при выключенной троичности. Оба дефекта исправлены
(`8825b05`, `064d69c`); числа выше — после починки.
