## Третий CE-попытка и закрытие оси

Triton-заготовка `scripts/kernels/triton_ce_backward.py` (round 33,
докстринг утверждал «verified») ФАКТИЧЕСКИ СЛОМАНА: rel_err = 1.0
при H=128, CompilationError при H=1152 (tl.dot shape constraint).
Докстринг лгал (или кернел сломался апгрейдом triton). Даже будучи
починенным, aten-путь 316ms < triton 529ms на H=128.

По 3-fail правилу (прямой LoRA-путь, fused+z-LSE, triton) — CE-ось
оптимизации ЗАКРЫТА. chunked CE остаётся; его 732ms bwd — принятая
стоимость до смены железа/сборки torch.

## Форма батча — A/B замер (равные токены)

| B×T | ms | us/1k tok |
|---|---|---|
| **32×1024 (текущий)** | 1660 | **50.7** |
| 16×1024 | 854 | 52.1 |
| 8×1024 | 435 | 53.1 |
| 16×2048 | 2027 | 61.9 |
| 8×2048 | 1013 | 61.8 |

Текущая форма 32×1024 — лучшая по токенам/сек; T=2048 хуже на 22%
(attention O(T²) съедает GEMM-выигрыш). Подтверждено: не трогать.

## Итоговая скорость линии

- compile on: −14% (уже в конфиге)
- batch 32×1024: оптимально (подтверждено A/B)
- CE-путь: chunked, локальный оптимум; 3 попытки ускорить — все
  отвергнуты измерением полного шага
- pinned/non_blocking H2D: отложено (историческая HIP-гонка; требует
  длинного верификационного прогона)

Скорость обучения стабилизирована. Дальнейшая оптимизация — только
смена версии torch/ROCm или triton-кернел с нуля (обе вне
Gittins-приоритета текущей программы).
