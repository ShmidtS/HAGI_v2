## Вердикты

### Muon — ПРИНЯТ, главный выигрыш раунда

−0.50 ната к AdamW на обоих seed, +6 мс/шаг (шум). Механика уже была в
коде (`use_muon: false` по умолчанию — теперь `true` в каноническом
конфиге). Это второй по величине выигрыш сессии после lr-фикса.

### NorMuon — ОТКЛОНЁН на нашем масштабе

Реализован минимально (RMS строк после Newton-Schulz, `muon.norm_rows`),
заявленные +11% к Muon на 1.1B НЕ воспроизвелись: у нас −0.15 ната ХУЖЕ
Muon на обоих seed. Гипотеза: на листе 8.7M с 3 слоями row-дисперсия
ортогонализованных обновлений мала, и нормализация строк режет полезную
асимметрию. Согласуется с обзором: «результат зависит от масштаба».
Код оставлен (`norm_rows: false` по умолчанию) — на больших телах
перепроверить.

## Порядок дальнейших кандидатов из обзора (не реализовано)

1. **MARS-M** (Muon + variance reduction) — следующая ступень по
   логике обзора; требует отдельной реализации var-reduction механики.
2. **ADANA-style память** — β(t),λ(t) от возраста ветви: для
   recursive-growth это концептуально новый класс (память привязана к
   эволюции блока, сбрасывается при merge). Кандидат в отдельный
   HAGI-оптимизатор, не в этот раунд.
3. **M+Adam** — multiplicative update для тернарной dead-zone: у нас
   листья не тернарные (ternary.enabled false), актуально только
   при возврате к тернарной базе.
4. Память состояния (APOLLO/Adam-mini) — у нас лист 8.7M, state копеечный;
   актуально для больших моделей.
