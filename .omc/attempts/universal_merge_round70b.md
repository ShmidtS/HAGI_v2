# Universal merge system — архитектурный каркас (round 70b)

## Цель
Система, принимающая ЛЮБУУ oss-модель как ветвь дерева HAGI:
θ_OSS → (tokenizer-мост) → (дельта/адаптер) → (R66-гейт) → merge.

## Пайплайн (4 интерфейса)

1. **Tokenizer-мост** (есть: vocab_map+gemma bridge; mergekit:
   union/tokensurgeon): θ_OSS эмбеддинги → наше 32768-пространство
   через пересечение словарей; OOV → fallback.
2. **Транспорт знаний**: два режима —
   a) distill: OSS-модель как учитель (логиты → KL) на общем
      корпусе — самый надёжный (наш distill.py уже существует);
   b) task-vectors: θ_OSS − θ_base через адаптер-проекцию
      H_OSS→H_наш (нужен новый модуль; mergekit task_arithmetic).
3. **R66-гейт**: CE(residual ветви против инкумбента) < 9.5 на
   доменных окнах — информация есть? (чужие модели почти
   гарантированно проходят: обучены на терабайтах).
4. **Merge**: block-diag (наш канон) или task-arith компрессия
   (mergekit), затем joint-фаза на канон-миксе.

## Приоритет реализации
distill-режим (2a) — не требует согласования размерностей,
масштабируется на любую модель, использует готовый код.
OSS-модель = бездонный источник новых данных (замена конечных
корпусов).

## Ждём
Обзор моделей (агент): кандидаты на первый импорт.
