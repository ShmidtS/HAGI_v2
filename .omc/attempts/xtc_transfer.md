# XTC (arXiv 2608.22758) — разбор и переносы в HAGI

## Что в работе

XTC (Exclude Top Choices) — head-aware оператор ДЕКОДИНГА: при ≥2 токенах
над абсолютным порогом τ, с вероятностью ρ удалить доминирующие, оставив
наименее вероятный из eligible, перенормировать. KL-проекция на носитель
(Prop 5), no-op при однозначной голове (Prop 1), шансы выживших неизменны
(Prop 2).

Результаты: Distinct-2 +11–15% монотонно 12B→70B; repeat trigram −27–47%;
человеческое слепое исследование (150 AMT Masters): 62.3% предпочтение
креативности при сохранении беглости; IFEval −1.7pp против −8.8pp у
matched-temperature (потому что XTC sparse-in-time: не трогает шаги с
однозначной головой >90%).

## Прямая применимость к обучению листа — НЕТ

XTC — преобразование выходного распределения при инференсе. Он не
меняет ни градиенты, ни CE, ни скорость шага. Встраивание в train loop —
категориальная ошибка. Не реализовано, и не надо.

## Перенос 1: генерация self-play данных (отложено)

Когда дойдём до самогенерации обучающего корпуса, XTC — готовый
инструмент против вырождения синтетики в повтор самого вероятного
(их §C.4, composition T1.3+XTC лучшая на всех 10 метриках). Параметры
для нашего масштаба подбирать по их границам: код/структура ломаются
при ρ>0.15–0.2.

## Перенос 2: head-ambiguity уточняет триггер роста (важно)

Наш FGD-принцип: «листья согласны → ёмкость исчерпана, concat бесполезен;
различаются → расти». Открытый вопрос был — как мерить согласие.

XTC §A.4 даёт точный ответ: **неопределённость ≠ энтропия**. Распределение
со скромной энтропией может иметь 2 сильных head-токена (XTC активен);
распределение с высокой энтропией из диффузного хвоста может иметь
один токен над порогом (XTC инертен).

Следствие для триггера роста: согласие листьев мерить не полным KL, а
**head-multiplicity**: сколько токенов у усреднённого листа выше τ на
held-out позициях. Много сильных head-кандидатов у среднего листа →
листья знают разное → concat. Один доминирующий токен → head
unambiguous → среднее честно, рост бесполезен.

Это объединяет три наших результата в одну шкалу:
- BTX-усреднение работало бы на согласованных головах (у нас проиграло
  0.26 — головы различались);
- flat concat выигрывает на различающихся (0.22 ната — подтверждено);
- XTC-критерий — формальная граница между этими режимами.

## Статус

- Идея записана, не реализована. Реализация: head-multiplicity метрика
  на held-out перед каждым concat-уровнем (~15 строк, без обучения).
- Прямая работа с XTC — только при генерации, не в train loop.
