# Раунд 7: MARS-M реализован и отклонён — variance reduction не платит на листе

## Что сделано

MARS-M (arXiv 2510.21800, официальный код AGI-Arena/MARS) реализован в
нашем Muon как `muon.mars_gamma`:

```
c_t = (g - last_grad) * gamma*mom/(1-mom) + g, clip norm<=1
```

Приближённая форма (`is_approx=True` upstream): last_grad = градиент
прошлого шага, без дополнительного backward. gamma=0 → чистый Muon.

Реализация: `src/hagi/train/optim.py` (поле `mars_gamma`, коррекция до
momentum-буфера), `MuonConfig.mars_gamma` в config.py.

## Замер (лист H=128, 800 шагов, held-out, sweep-scale, seed 3001)

| вариант | CE |
|---|---|
| Muon (g=0) | 4.8972 |
| **MARS-M g=0.005** | **4.8916** |
| MARS-M g=0.025 (upstream дефолт) | 4.9223 |
| MARS-M g=0.1 | 4.9796 |

## Вердикт: ОТКЛОНЕНО

Кривая gamma замерена: оптимум ~0.005 даёт 4.8916 против Muon 4.8972 —
разница 0.006 ната, глубоко в шуме. Дефолтный 0.025 хуже на 0.025,
0.1 хуже на 0.08. **Variance reduction не покупает ничего на листе
H=128 / 800 шагов.**

Гипотеза несоответствия: MARS выигрывает при длинных горизонтах и
больших batch, где накопленный шум стохастического градиента велик
(их эксперименты — GPT-2 на 480 токенов/шаг с accum 40). Наш лист
32k токенов/шаг и короткий горизонт — шум уже мал.

## Из твоего обзора остаются нереализованными

- ADANA-style память (β/λ от возраста ветви, сброс при merge) —
  концептуальный HAGI-оптимизатор, требует дизайна, не патча.
- Schedule-Free — кандидат для recursive growth (обучение без горизонта);
  требует замены schedule-механики.
- Память состояния (APOLLO/Adam-mini) — не актуально на 8.7M.

Оптимизаторная ось исчерпана: Muon — потолок для этого масштаба.
