# Раунд 14: формализация → триггер v2 (Lean-предписания в коде)

## Что перенесено (Select/Concat/Ambig → growth_gate.py v2)

Формализация (lake build зелёный, 0 sorry) дала три предписания;
все вшиты в исполняемый триггер:

1. **certifiedGain(N, M, c) = (M−c)/(N+1)** (Select.lean newBound):
   сертифицированная граница нового mean-CE пула после добавления
   кандидата, вычислима ДО шага (аналог FGD U_t). Кандидаты ранжируются
   по gain (граница корректна: certifiedGain_monotone), НЕ по
   standalone CE как решающим правилом (selection_hurts — теорема-
   контрпример).
2. **grow_epsilon_stop**: если лучший кандидат certifies < ε — все
   дают < ε: ось GROW сертифицированно исчерпана, остаётся EXHAUSTED
   (данные). В коде: `--candidate-configs` + verdict override.
3. **speed stop** (Ambig.lean consensus_no_gain): ожидаемый выигрыш
   следующего листа ~ spread²/(N(N+1)); стоп при < ε². τ перестала
   быть константой — стала вычислимой скоростью.

## Живая проверка (лестница v3, gate-окна)

- Воспроизводимость: flat9 замер ce 7.2096 / amb 0.0395 совпал с
  прежним прогоном бит-в-бит.
- Валидная цепочка flat6→flat9: SATURATED-AMBIGUITY (как раньше).
- Кандидатный режим: leaf_v3_canonical CE 7.00 → certifiedGain
  +0.0206 ≥ ε → ось GROW НЕ исчерпана сертифицированно; leafdat_b2
  (CE 7.62) — gain −0.041, отвергнут границей до любого merge.
  Решающий вердикт остался SATURATED: эмпирический ambiguity-
  дрейф переопределяет консервативную границу — честная иерархия
  (сертификат = нижняя граница, не решение).
