# Round 69 (дизайн): ВОЗВРАТ К ДЕРЕВУ — ортогональные доменные ветви + task-arithmetic слияние

## Замечание пользователя (курс-коррекция, верная)

Исходная идея HAGI — ДЕРЕВО с ортогональными корпусами по ветвям.
Линия dbridge ушла в линейную цепочку (LoRA-deepen), а сибы на
ОБЩЕМ миксе (R66/67) доказанно схлопываются в одну функцию.
Но gen-1 листья (каждый на СВОЁМ подмножестве) имели реальный
gap 0.078 — ортогональность доменов работала с самого начала.

## Mergekit-находки (librarian, arcee-ai/mergekit)

- **task_arithmetic**: θ = θ_base + Σλᵢ(θᵢ−θ_base) — дельты от
  общего prior'а аддитивны; при ортогональных доменах дельты в
  разных подпространствах → нет интерференции. Размер модели
  СОХРАНЯЕТСЯ (в отличие от block-diag ×N).
- **TIES**: trim top-δ% + sign election — при многих ветках.
- Наш block-diag merge остаётся каноном для lossless-step-0;
  task-arith — второй инструмент для СЖАТИЯ дерева (уровень
  «compress» макро-цикла).

## Gen-3 дизайн (дерево, ортогональные ветви)

```
record r48 (prior)
├── leaf-MATH:  only camelmath+openwebmath    (1600 шагов)
├── leaf-CODE:  only python_instruct+edu      (1600 шагов)
└── leaf-RU:    only wikipedia_ru+oscar_ru    (1600 шагов)
        ↓ merge: block-diag (lossless) + hadamard
        ↓ joint: 1600 шагов на канон-миксе
        ↓ опционально: task-arith компрессия дельт обратно в H=384
```

- Каждый лист = СВОЙ домен (не общий микс) → residual-компонента
  обязана быть информативной (R66-тест как go-гейт перед merge).
- Прогноз (prereg при запуске): если ортогональность жива,
  residual CE(leaf-MATH) << 10 на math-окнах; ансамбль > 3.34.

## Очередь

1. data-joint завершается (текущий ран) — его результат фиксирует
   baseline для новых корпусов.
2. Три доменных листа (3×40 мин GPU).
3. R66-гейт на каждом листе → merge только при информативном
   residual.
4. Merge+joint; сравнение против 3.3686.
